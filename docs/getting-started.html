Getting started

Install Kyon, answer the first-run introduction, find your way around the window and start your first coding agent.

Install Kyon

Kyon installs as an ordinary Mac application, so it updates and uninstalls like any other.

  • With Homebrew: run brew install --cask kyon-sh/kyon/kyon. The cask installs Kyon.app and replaces an earlier Kyon if you had one.
  • By download: get the latest build from kyon.sh and move Kyon.app to your Applications folder.

To check for a newer build later, choose Check for updates from the Kyon menu or the command palette (⌘P). The answer appears on the About page, which says how the check stands and offers to install the build it found. About Kyon, in the Kyon menu, shows the version and update channel you are on.

The first-run introduction

The first time a window opens, a short introduction sets Kyon up around the tools you already use. Each screen is a list: choose a row with the arrow keys and ↩, or click it. Continue moves on and Back returns to the previous screen. Nothing in it asks for an account.

  1. A terminal for your coding agents. What Kyon is for.
  2. Which coding agent do you use? Choose Claude Code, Codex, Gemini, OpenCode or Pi, or None of these. Kyon is built around these agents, and your answer decides what the next questions offer.
  3. Pick a theme. Every theme Kyon has, including any of your own.
  4. How should Kyon's own agent answer? Kyon has its own agent for questions on the side. It can answer:
    • With the coding agent you chose, nothing to set up: Kyon runs that agent once for each question. Offered for Claude Code, Codex, Gemini and OpenCode.
    • I have an API key: the key is stored in your keychain, never in the settings file.
    • A command mints a token: for endpoints that hand out short-lived tokens.
    • A local server that needs no key.
    • No model for now: the terminal and the coding agents work the same either way.
  5. Where is it? Shown only when you chose a key, a token command or a local server. Give the endpoint's URL and model name, whether it speaks openai or anthropic, the key or token command, and optionally a name. Continue stays greyed, with the reason beside it, until the URL and model are filled in.
  6. What may it do on its own? Also only with an endpoint: Ask before it changes anything (reads files freely, asks to write or run), Ask before everything, reading included, or Never ask.
  7. Where do you work? A folder for new tabs, under Start new tabs in.
  8. A few preferences. Text size, an opaque or slightly see-through window, whether to bring your windows back next time, and whether to be told on the desktop when an agent needs you.
  9. Ready. A summary of your choices. Choose Finish to save them.

Your answers are written to your settings file, and the window says where it saved them. If you turned on desktop notifications, macOS asks for permission straight away.

Choosing a folder there sets New terminals start in (Settings › Terminal › General) to start every new terminal in it. Leave it empty and a new terminal opens where the one in front is working.

If you press Esc or click outside the list before the end, the introduction closes, nothing you were choosing is applied, and it does not open again by itself. To see it again, choose Show the introduction again from the Kyon menu or the command palette. It opens with your current theme already chosen.

Hints

After the introduction, Kyon shows a short hint now and then, at most one a day, about splitting panes, the command palette, agent conversations and restoring your windows. Each hint goes away on its own once you have had time to read it, and is not shown again. Show the hints again brings them all back.

A tour of the window

Everything in a Kyon window is a tab made of panes, so the same few gestures work for terminals, agents, files and settings.

The title bar

Tabs run along the top by default, in the title bar. Buttons sit on either side:

  • Left: one button shows or hides the vertical tab list, and another opens Go to session (⌘⇧O), a list of your tabs to filter by name. With the vertical tab list showing, a third button docks the file tree beside your panes, and the middle of the bar becomes a search field, Search sessions, agents, files..., that opens the command palette.
  • Right: the round button at the far right is your menu. It holds Check for updates, What's new, Settings, Keyboard shortcuts, Documentation, Feedback, View Kyon logs and About Kyon. Beside it is the inbox, which lists what the window has told you. A globe appears when you have remote targets set up, and while the tab in front is in a Git repository a review button appears, with the lines added and removed on the branch.

Tabs

Each tab holds one or more panes. ⌘T opens a new terminal tab, and ⌘1 to ⌘8 go to a tab by position. A tab with an agent waiting for you carries a blue dot. If you prefer tabs down the side, where each pane gets its own row, run Toggle vertical tabs. Tabs, panes and windows covers all of this in full.

Panes

Split the pane you are in with ⌘D (right) or ⌘⇧D (down), and move between panes with ⌘] and ⌘[. The pane with the keyboard focus is marked at its corner. Right-click a pane to see what you can do there.

The command palette

Press ⌘P to open the command palette. It lists every command with its shortcut, and every on/off setting with its current value. Type to narrow it. Once you type, it also finds open sessions and files in the session in front.

The side panel

A panel can sit beside your panes. It has three views, each on its own key:

ViewShortcut
Left Panel: Project explorer⌃1
Left Panel: Agent conversations⌃2
Left Panel: Global search⌃3

Pressing a view's key while it is showing puts the panel away. You can also dock the file tree with ⌘⇧B, the outline of the file in front with ⌘⌥B, or every agent with Dock the agents beside the panes. Docked panel in Settings › Appearance › Layout picks the panel a new window opens with.

The menu bar

The menu bar holds the commands you reach for most: File, Edit, Code, View, Tab, Session and Window. The Kyon menu holds settings, updates, help and the introduction. Every command, including those left out of the menus, is in the command palette.

Open your first agent

A coding agent runs in a terminal tab of its own, where Kyon can show what it is doing and tell you when it needs you.

  1. Press ⌃⌘T to open the new-session menu. With the vertical tab list showing, its new-tab button opens the same menu.
  2. Choose your agent: Claude Code, Codex, Gemini, OpenCode or Pi.
  3. A panel beside the menu asks where it runs. Choose Local for this Mac, one of your remote targets, or Manage targets… to add one.
  4. Kyon asks which folder to start in. The first row, Launch followed by the agent and folder, starts it where a new tab would start. Type a path to go elsewhere: the folders inside it are offered as you type, and Tab goes into the first one; folders you used before are listed, and on this Mac Browse… opens the folder chooser.

You can also start an agent the usual way, by typing its command (such as claude) in any terminal. Kyon recognises it however it was started.

When you run an agent Kyon can connect to, Kyon offers to install that agent's Kyon plugin, once on each machine. Accept it so the agent can report each turn and question to Kyon. To start a conversation with Kyon's own agent instead, press ⌘I (New agent conversation).

Once agents are running, ⌘J takes you to the next one waiting for you, and ⌘⌥A shows every agent in every window, with the ones waiting for you first.

Limits

A screen reader can read the Kyon window, but cannot yet move the focus or activate anything in it. The project explorer shows one root for the whole window, the window's own, rather than one for each folder your panes are in, and keeps one filter for the window rather than one for each tab.
