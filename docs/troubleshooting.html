Updates and troubleshooting

Keeping Kyon up to date, where it keeps your settings and logs, and what to do when something looks wrong.

Keeping Kyon up to date

Kyon looks for a new release only when you ask, so it never contacts the release server on its own schedule.

  1. Run Check for updates from the command palette (⌘P) or the Kyon menu. Settings opens on the About page, which shows your version and update channel.
  2. The About page says how the check is going. If there is a newer release, Kyon downloads it and checks it against the published checksum before offering it.
  3. Press Install with the new version number. Kyon verifies the build's signature, puts it in place, and tells you to restart to run it.

If you installed Kyon with Homebrew, brew upgrade --cask kyon updates it too.

Release channels

Settings › General › About shows which channel you are on, and Which releases to offer in Settings › Terminal › General chooses it: stable, beta or nightly. Stable is what most people should use. Moving back from beta or nightly to stable does not undo a newer build already installed; you go back to stable releases from the next one that is newer.

What changed

After an update, the first window says once that Kyon was updated, with a link to what changed. View latest changelog (⌥⇧⌘O) opens it at any time, as does What's new on the About page. To stop the notice, turn off Show changelog toast after updates in the same place.

Where Kyon keeps your files

On a Mac everything is under your Library folder:

WhatWhere
Settings, key bindings, saved commands, launch configurations, restored sessions~/Library/Application Support/com.ryowave.kyon
Logs~/Library/Logs/com.ryowave.kyon
Caches~/Library/Caches/com.ryowave.kyon

The settings are in settings.toml and the key bindings in keybindings.toml. Run Open settings file (⌥⌘,), Open keybindings file or Show the settings folder from the palette to reach them, and View Kyon logs to open the folder of logs.

Beta and nightly builds keep their files in folders of their own, named with the channel after them (for example com.ryowave.kyon-beta), so trying one never touches your stable setup.

When the settings file has a mistake

Kyon re-reads the settings file within a second of it changing. If a value in it cannot be used, Kyon sets that value aside, keeps the rest, and says so in a band at the top of the window and at the foot of the Settings window. From there you can open the file, or, with AI on, ask an agent to fix it. Re-read the settings file applies the file again after you have edited it elsewhere.

When something looks wrong

  • A message went by too fast. What this window has said lists the window's recent notices.
  • A hint you dismissed is gone. Show the hints again brings them back, and Show the introduction again runs the first-run introduction once more.
  • An agent is not recognised in a terminal. See Coding agents for how Kyon recognises one, and install Kyon's plugin for it when offered.
  • A server can't be reached. See Working on a server. Kyon connects with your own SSH configuration, so check that ssh to the host works in a terminal first.
  • Kyon quit unexpectedly. Start it again: your tabs, splits and sessions come back as they were.

Telling us about it

Run Feedback from the palette or the menu behind the button at the right of the title bar; Feedback says where reports go and what makes one easy to act on. The version on the About page (its copy button copies it) and the log from View Kyon logs help most.

Removing Kyon

With Homebrew, run brew uninstall --cask kyon; otherwise move Kyon from Applications to the Bin. Your settings and sessions stay in the folders above, so a later install picks up where you left off. Delete those folders as well to remove everything.
