Tabs, panes and windows

Arrange your work in tabs, panes and windows, save layouts, change how Kyon looks, edit settings, and get everything back after a restart.

Tabs

Tabs keep each piece of work, whether a shell, an agent, a file or the settings, one keystroke away.

CommandShortcut
New tab⌘T
New session menu⌃⌘T
Close tab⌘⇧W
Next tab / Previous tab⌘⇧] / ⌘⇧[
Go to tab 1–8 / Go to last tab⌘1–⌘8 / ⌘9
Move tab left / Move tab right⌘⇧, / ⌘⇧.
Rename tab⌘⇧R
Pin or unpin tab⌘⇧P

New tab opens a terminal, or the tab configuration named in New tabs use (Settings › Terminal › General). Open new tabs (Settings › Terminal › Behavior) places new tabs at the end or after the current one. Drag a tab to reorder it. Pinned tabs stay together at the front.

The new-session menu

The new-session menu starts any kind of session in one place. Open it with ⌃⌘T, or with the vertical tab list's new-tab button (along the top, that button opens a plain new tab). It offers Agent for Kyon's own agent, each coding agent (Claude Code, Codex, Gemini, OpenCode and Pi), Terminal, your saved tab configurations, and Reopen closed session. A coding agent or terminal first asks where it runs: Local, a remote target, or Manage targets…. A coding agent then asks which folder to start in; Coding agents covers this step.

Tabs along the top, or down the side

Tabs run along the top of the window by default, in the title bar. Run Toggle vertical tabs, or use the button at the left of the title bar, to list them down the side instead. There, each pane gets its own row with its branch or folder beneath, and a search field finds a tab. The tab settings, including Vertical tabs and Show the tab bar, are in Settings › Appearance › Layout.

When more tabs are open along the top than fit at a readable width, the rest are counted at the end as +N. Click the count to find one by name.

Knowing which tab needs you

A tab that is waiting for you carries a blue dot, along the top and in the vertical list alike. A tab waits when an agent in it is asking something, when an agent's answer has not been read yet, or when it rang the bell. Sort tabs by agent status keeps tabs whose agent needs you first.

Hover a tab to see its card: what its agent is doing, its title, branch and folder, what kind of session it is, and the lines changed there.

Names and colours

Tabs take their title from the shell until you use Rename tab. Reset tab name undoes a rename.

Right-click a tab for its menu. Along with renaming, closing, copying the branch or working directory, and saving the tab as a configuration, it has a row of colours. With several panes in a tab, opening the menu from a pane's row colours that pane. Cycle tab colour steps through the colours from the keyboard.

Colouring tabs by rule

Rules let a tab change colour by what it is doing, such as turning red while it is on a production machine. Write them in your settings file: Tab color rules in Settings › Appearance › Layout has an Edit in settings file link.

Each rule is a [[tabs.colour_rules]] table naming any of user, host, path and command as * and ? patterns, and a colour. The first rule that fits wins. A table with host = "prod-*" and colour = "red" turns a tab red while it works on any host whose name starts with prod-. While sudo, su or ssh runs, the tab counts as the user or host it reached. To colour by folder alone, list folders under [tabs.directory_colours], such as "~/src/website" = "blue".

The colours are red, orange, yellow, green, blue, purple, grey and none. Rules are tried before directory colours, and a colour you set on a tab by hand always wins over both.

Panes

Panes keep related work side by side, such as an agent beside the shell it is changing.

Right-click inside a pane for what it offers there, along with splitting and, in a tab of several panes, maximising and closing. The focused pane is marked at its corner. Show pane headers names each pane above it, by default only when a tab has several. Closing a pane while a command runs in it asks first.

To type into several shells at once, run Synchronise input in this tab (⌘⇧I) or Synchronise input across this window, and Stop synchronising input when you are done.

Windows

Separate windows keep separate projects apart.

  • New window (⌘N) opens a window with a terminal tab. Move tab to the next window sends the tab in front there.
  • Hide all windows (⌘H) and Show all windows (⌘⇧N) put every window away and bring them back.
  • Fill the screen (⌃⌘F) makes the window full screen.
  • Global hotkey window (Settings › Terminal › Input) sets a shortcut that shows and hides a window from anywhere.

Layouts and launch configurations

Configurations open a tab, or a window's worth of tabs, ready-made in the right folders.

A tab configuration describes one tab. Run Save this tab as a configuration to save the tab in front under a name. It records each pane's folder, the tab's colour and any title you gave it, but not what the panes were running or their sizes. Open one with Open tab configuration or from the new-session menu.

A launch configuration is a set of tabs. Open launch configuration opens its tabs in the current window, and Save this window as a launch configuration saves one with an entry for each tab in the window. Both commands are under Window › Launch Configuration.

Configurations are TOML files you can edit by hand, in the tabs and launch folders beside your settings file. The file name is the configuration's name. A tab configuration can set:

  • title: the tab's name, such as title = "API".
  • colour: one of the tab colours, such as colour = "green".
  • One [[pane]] table for each pane, with cwd for the folder it starts in and command for what it runs instead of the shell, such as command = "npm run dev".

Each [[pane]] after the first is split from the one before it, right or down. A launch configuration is one or more [[tab]] tables in the same form, with any panes written as [[tab.pane]].

The command palette

Everything Kyon can do is in the command palette, even what is not in a menu or bound to a key.

Press ⌘P. The palette lists every command with its shortcut, and every on/off setting with its current value, which you can choose to flip. Type to narrow the list. Once you type, it also finds open sessions and files in the session in front. To search one kind only, start with actions:, sessions: or files:.

Keyboard shortcuts lists every command with its keys, including commands with none. To change a binding, use Settings › Terminal › Keyboard shortcuts, or Open keybindings file.

Themes and appearance

A theme and text size that suit you make long sessions easier on the eyes.

  • Choose theme lists every theme. In Settings › Appearance, the Theme row opens a chooser beside your panes that shows each theme by example and redraws the window in the one you select.
  • Follow system appearance switches between a Light theme and a Dark theme with macOS.
  • Your own themes are TOML files in the themes folder beside your settings file. Run Reload themes after editing one.
  • Zoom in (⌘=), Zoom out (⌘-) and Reset zoom (⌘0) change the size of the text.
  • Window Opacity and Interface scale are in Settings › Appearance › Layout, and fonts in Settings › Appearance.

Settings and the settings file

Change Kyon in the Settings tab or in a plain text file, whichever suits you.

The Settings tab

Press ⌘, (Open settings) to open Settings in a tab, or switch to it if it is already open. Its search field finds a setting by name. A change takes effect at once and is saved to your settings file. Settings lists every setting.

The settings file

Settings are stored in settings.toml. The Kyon menu's Settings Files submenu has the commands for it:

  • Open settings file (⌘⌥,) opens it in Kyon's editor.
  • Open keybindings file opens keybindings.toml.
  • Re-read the settings file reads both files again.
  • Show the settings folder opens the folder in Finder.

Kyon notices when either file changes and applies it within about a second. A change made in the Settings tab replaces only that value in the file and keeps your comments.

When the file has a mistake

If the settings file has a mistake, a band across the top of the window says Your settings file contains an error. and names each problem. A value that cannot be used falls back to its default. If the file cannot be read at all, every setting uses its default and nothing is saved to it until it is fixed. The band offers Open file and, while AI is on, Fix with Kyon, which asks an agent in a new tab to put the file right. Once you close the band, the same warning appears at the foot of the Settings tab's page list until the file is fixed.

Restoring after a restart or a crash

Your windows, tabs and panes come back when you start Kyon again, even if it stopped unexpectedly.

With Restore the last session on (the default, in Settings › Terminal › General), Kyon reopens every window where it was, with its tabs and panes. The layout is saved whenever it changes, so a crash loses little. A restored terminal shows its last blocks of output, read-only. Restored history sets how many.

With Keep shells running on (the default), terminals run in a separate session host. After a crash, a shell and what it was doing go on, and the pane comes back to it. When you quit, the shells end unless you choose to keep them, and the tabs come back with new shells in the same places.

If Kyon fails to start twice in a row, the next launch begins with an empty window rather than opening the saved session again.

Quitting and closing

Kyon asks before a quit would end shells you may still need.

Quit Kyon (⌘Q) with tabs open asks Quit Kyon? and offers Quit or Keep Shells and Quit. Keeping them lets the tabs come back to the shells as they were. Tick Don't ask again to make your choice the default; change it later with Ask before quitting and Keep shells running after quitting in Settings › Terminal › General. Running Close window on a window with more than one tab asks Close this window? first.

Undo close

Closed something by mistake? Reopen closed tab (⌘⇧T) brings back the most recently closed window, tab or pane. Each closed item can be reopened for 60 seconds by default. Change this with Undo close window (Settings › Terminal › General), or set it to 0 to turn reopening off. A change applies after Kyon restarts.
