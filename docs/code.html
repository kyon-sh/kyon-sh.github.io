Code, review and documents

Open and edit files with language servers, search the workspace, write Markdown in place, and review, comment on, commit and hand off your git changes.

Open files

You can reach any file in the project from the keyboard, by part of its name or by its path.

  • Press ⌘O (Open a file) or ⌘E (Browse files). With nothing typed you see the project's tree; type and it searches the whole tree. Choose a file to open it.
  • Type a path starting with / or ~ to open that exact file. Add :line, as in main.rs:120, to land on that line.
  • If nothing matches, Create a file named … opens a new file at the top of the project.

In an open file, ⌘L (Go to line) moves the caret to a line number. Files open in a split at the right of the tab unless you change it on Settings › Code › Editor and Code Review.

The editor

The editor handles everyday editing, and adds language intelligence where a language server runs.

  • Several carets: ⌥-click to add one, or ⌃⌥↑ / ⌃⌥↓ to add one above or below. Select this, then the next one like it (Edit › Carets) adds the next match. Esc returns to one caret.
  • ⌘/ comments or uncomments lines. ⌘⌥- folds or opens a block, ⌘⌥⇧- opens every fold, and ⌘⌥Z switches line wrapping.
  • Find: ⌘F opens the find bar with the selection in it. ↩ / ⇧↩ (or ⌘G / ⌘⇧G) step through matches; .* and Aa switch on regular expressions and matching case; Select all puts a caret on every match. The chevron at the bar's left shows Replace and Replace all.
  • Save: ⌘S. With a language server running, the file is formatted first. If the file changes on disk under unsaved edits, a strip above the code offers Overwrite or Discard this version.

Language servers

A language server gives you completions, definitions, references, renames and problems marked as you type.

Kyon can install rust-analyzer, gopls, pyright, typescript-language-server and clangd. Open a file in one of those languages and the bar along the bottom of the file offers to Enable the server for the project, or to Install it, on the machine the file is on. Once enabled, it starts whenever you work in that project. The bar's dot is green when ready, yellow when busy and red when failed; the lightning icon opens a menu to view logs, restart, stop or start it.

The file explorer

The project explorer keeps the tree beside your panes, on this Mac or a host.

Press ⌃1 (Left Panel: Project explorer) or ⌘⇧B (Dock the file tree beside the panes). Type in the field above the tree to filter it: letters in order match, ignoring case, so vw finds view.rs, and uni/tes matches along a path. When you pause, Kyon searches the whole tree and opens the first matches into it. The buttons beside the field switch to a regular expression, show a flat list, refresh and clear.

Look through a path, at the bottom of the panel, adds another folder, such as ~ or ../other-repo, until you remove it with the cross on its row.

Search the workspace

Workspace search finds text in the folders the tab is working in, and keeps the results beside your panes.

Press ⌘⇧F (Search the workspace) or ⌃3. The search runs when you pause typing; the regex and case toggles change how it reads the query. ⇥ moves to the folders field, a comma-separated list such as src, *.md, !vendor. Results are grouped by folder and file; ↓ moves into them and ↩ or a click opens a match at its line. Each tab keeps its own search.

Markdown documents

Markdown files open rendered, and you write in the rendered page.

The block holding the caret shows its source, with the marks faintly visible, while the rest stays rendered. ⌘⇧E (Markdown: switch between rendered and source) switches to the raw source and back.

A formatting bar above the document inserts headings, bold, italic, code, lists, task lists, quotes, links, pictures and tables. Link and Picture ask for the address in the bar, suggesting files beside the document (⇥ takes one) and, after #, headings in this or another document. Choose a file picks one instead.

  • Pictures beside the document, embedded in it or on the web are shown in the page.
  • A mermaid code block is drawn as a diagram, offline.
  • Clicking a link to a heading opens its document at that heading.

Review changes

The review takes you from reading your changes to a commit, a push and a pull request.

Open a review

In a git repository, the review control at the window's top right shows the lines added and removed across the whole branch, committed or not, against the branch it grew from. Click it or press ⌘⇧= (Toggle code review) to open the review in a panel at the right; each tab keeps its own. ⌘R (Review changes) opens one in its own tab.

Read and compare

Press n / p for the next or previous change and ] / [ for the next or previous file; ⌘⌥E shows more above a change and ⌘⌥S switches to what is staged. The review starts with uncommitted changes. Press c or ⌘⌥⇧R (Review a branch, a commit or a pull request) to compare against another branch (likely parent first), a recent commit or an open pull request; ⇥ sets whether uncommitted changes are included.

Comment, discard, commit

  • Hover at the left edge of a line and click the button that appears to comment. The tray at the bottom counts comments; Send to Agent pastes them into the coding agent in this tab, and Cancel discards them all.
  • ⌘⌥⌫ (Discard the changes to the file being reviewed), pressed twice, throws away the file's changes.
  • The header's button offers the next step: Commit, Publish, Push, Create PR, or the open pull request. The commit dialog lets you choose Commit, Commit and push or Commit and create PR with ↑ / ↓. Pull requests need the GitHub CLI, gh, signed in.
  • The panel's ⋮ menu offers Delegate fixes to agent and Review with agent, which adds the agent's findings as comments. It uses the coding agent chosen in Ask with (Settings › Agent › Agent), or Claude Code. For reviewing an agent's last turn, see Coding agents.

Notes on lines

Notes let you mark lines while you read and hand them to an agent later. They are the same comments the review shows, kept per repository.

  • In the editor, hover a line and click the button by its number, then Comment. The bar under the code has Send to agent.
  • Leave a note on this line notes the caret's line; Notes on this tree lists every note; Hand the notes to the assistant types them into the focused prompt. All three are in File › Notes.

Editor and Code Review settings

Settings › Code › Editor and Code Review (⌘,) sets which editor opens file links and files from Kyon's panels, whether files open as a split or a new tab, whether Markdown opens rendered, whether the review button and its line counts show and the review opens on an agent's first change, the explorer and search limits, Format on save, Tab width and Wrap long lines. See the settings reference and the shortcuts reference.

Limits

Project explorer: one tree per window, the window's, with one filter per window, focused by clicking its field. A folder added with Look through a path is searched only among what it has listed. On a host, it reaches its starting folder, home and temporary folders.

Workspace search: it searches one machine at a time, does not say a host is still connecting (an unreachable one reports failure), shows no full-path tooltip, and a host's results arrive at the end, capped at 20,000 lines.

Commits and pull requests: the commit message starts empty and a pull request is filled from its commits; no model writes them.

Handing a review to an agent runs a coding agent's command line where the repository is; a configured orchestration backend is not used. Codebase indexing is this Mac's only.
