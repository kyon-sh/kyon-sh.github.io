Kyon's agent, models and privacy

Talk to Kyon's own agent in a pane or the terminal, choose what answers it, keep private folders private, and give it rules, MCP servers and an indexed codebase.

Turning AI on and off

One switch controls every AI feature, so you can turn them all off at once.

Turn AI features on or off in Settings (⌘,) › Agent › Agent, or run Disable AI or Enable AI from the command palette (⌘P). While AI is off, Kyon's agent commands tell you they need AI enabled, and the settings that depend on it are greyed out, keeping their values. Coding agents you run in a terminal keep working, with their toolbar and notifications; see Coding agents.

Talking to Kyon's agent

Kyon's agent reads your project, edits files and runs commands, in a pane of its own or in the terminal you are already using.

In a pane

  • New agent conversation (⌘I) opens one in a new tab. Agent beside this pane and Agent below this pane (Session › Agent Pane) open one next to your work.
  • The line under the prompt shows the model, whether it is working (esc stops it) and the tokens used.
  • Session › Conversation has Change the model for this conversation, Show what tools returned and Clear this conversation (⌘⇧K).

In the terminal

Write in the terminal's input and press ⌘↩ (Ask an agent about what is written):

  • A request in plain words is turned into the command that does it, placed in the input for you to read and run. Press ⌘↩ again on that command to give your original request to the agent instead.
  • A command is asked about.
  • An empty input starts a conversation.

The conversation takes over the pane; esc goes back to the shell, stopping the agent first if it is working.

Under a command that is still running, ⌘⇧↩ brings the agent in: it can read what the program shows and type into it, asking first. Turn on Show "Use Agent" footer in Settings › Agent › Agent to have this offered under every running command.

Ask on the side, beside the coding agent in front (⌥⌘I) opens a conversation next to a coding agent; Kyon's agent is told what that agent is doing and leaves the work to it.

What the agent can do, and how much it asks

The agent works through a set of tools, and you decide which it may use without asking.

  • Read files, list directories and write files in the workspace.
  • Run a command in your terminal, where you see it run.
  • Read a terminal and type into the program running there, when the conversation is in that terminal or was brought in under a running command.
  • Search the codebase, once it is indexed.
  • Use tools from MCP servers.
  • List the coding agents running in every Kyon window, read what one was asked and answered, give one a prompt, and wait for it to finish.

File tools stay inside the workspace, whatever you allow.

Set how much it asks with What the assistant may do on its own in Settings › Agent › Profiles:

ChoiceWhat it does
Ask changes (default)Reads freely; asks before writing a file, running a command, typing into a terminal, prompting a coding agent or calling an MCP tool.
Ask everythingAsks before every tool call, reading included.
FreelyAsks about nothing: a decision to trust it with this machine.

When it asks, it shows the call exactly as it will run. In a pane, press y to allow or n to refuse; a refusal goes back to the agent so it can try another way.

Answering with a coding agent or a model

Kyon's agent can answer with a coding agent you already use, with nothing to set up, or with a model you configure.

Choose under Settings › Agent › Agent › Ask with.

  • Claude Code, Codex, Gemini or OpenCode: that agent's command line runs once per question, in your working directory on this Mac, signed in as you already are. It uses its own tools rather than Kyon's. Reviews you hand to an agent go to the one chosen here.
  • Models: a model set up under Settings › Agent › Models answers, using Kyon's tools and permission setting.

Setting up a model

Settings › Agent › Models takes any endpoint speaking the OpenAI-compatible or Anthropic Messages protocol, on this Mac, your network or a provider.

  1. Click + Add custom model, or one of Ollama, llama.cpp, LM Studio and vLLM beside Local model server: to start with its usual address filled in.
  2. Fill in Endpoint name and Endpoint URL. An address beyond this Mac and your local network must use HTTPS.
  3. Enter an API key if needed; a local server usually needs none.
  4. Choose the API shape: OpenAI compatible or Anthropic Messages.
  5. Under Who sees what is sent, choose Only me: private or A model provider. The address suggests one: this Mac and private network addresses count as private.
  6. Add models by Model name, with an optional Model alias for the picker, or click Fetch models to ask the endpoint. Then click Add endpoint.

Auth token command runs a command that prints the key, such as op read op://Private/OpenAI/key, and Token TTL in seconds sets how long its output is reused (0: never). Extra header name and Extra header value add a header a gateway needs. Keys are kept in the macOS keychain, not the settings file, and go only to their own endpoint.

Set the model new conversations use with Model in Settings › Agent › Profiles, written endpoint/model; switch one conversation with Change the model for this conversation.

Private models and private folders

Mark folders whose contents only a model of your own may read, and Kyon's agent keeps to such a model whenever it works there.

Run Mark this folder private, or not: Kyon's agent there uses only a private model (Session › Every Agent) for the folder in front, or edit Private places in Settings › Agent › Agent: a path, HOST:path on a remote host, or HOST: for all of one.

In a private place, Kyon's agent:

  • uses only a model marked private, never a coding agent, whatever Ask with says;
  • shows · private after the model's name;
  • does not answer when no model is marked private, and tells you to mark one in Settings › Agent › Models.

When a coding agent needs private data

A coding agent on a provider's model can get answers about private data without reading it. Once it is connected to Kyon, through Kyon's plugin or Connect the agent in front to Kyon: its status, and Kyon's tools, it can ask Kyon's private agent. That agent reads what it needs where the coding agent works, changes nothing, and answers in words, told to give only what the question needs.

Before the answer goes back, Kyon shows it to you: send it, allow that agent for the rest of its session, or don't. Turn off Ask before a private answer goes to a coding agent to send every answer as it comes.

With Settings › General › Privacy › Secret redaction on, likely secrets are replaced with asterisks in everything Kyon's agent sends to a model.

Rules files

Rules let the agent follow your conventions without you repeating them.

A new conversation reads ~/.agents/AGENTS.md on this Mac, then the KYON.md or AGENTS.md of each folder from the repository's root down to where it works, KYON.md first where a folder has both.

Settings › Agent › Knowledge has the Rules switch, and Manage rules, which opens ~/.agents/AGENTS.md, creating it if needed.

MCP servers

Kyon finds the MCP servers you set up for other coding agents and lends their tools to its own agent.

Settings › Agent › MCP servers lists them. My MCPs shows those running, with their tools and Stop (plus View logs and Start after a failure). Detected from Kyon, Claude, Codex and Other Agents show the rest, each with Start.

AgentHome folderRepository
Kyon~/.kyon/.mcp.json.kyon/.mcp.json
Claude~/.claude.json.mcp.json
Codex~/.codex/config.toml.codex/config.toml
Other agents~/.agents/.mcp.json.agents/.mcp.json
  • Servers in ~/.kyon/.mcp.json always start.
  • Those in other agents' home files start while Auto-spawn servers from third-party agents is on (off by default).
  • Those in a repository are listed once a terminal has been there, and start only from their card: cloning a repository is not agreeing to run what it names.

To add your own, list it in ~/.kyon/.mcp.json under mcpServers, with a command (and optional args, env, cwd) or a url (and optional headers). ${NAME} reads an environment variable; if one is unset, none of that file's servers start.

A conversation gets the tools of your home folder's servers and of its own repository's. An MCP call counts as running a command, so by default the agent asks first.

Indexing a codebase

An indexed codebase lets the agent go straight to the code a question is about.

Type /index in a terminal inside a repository, run Index This Codebase from the palette, or click Index new folder in Settings › Code › Indexing and projects. Turn on Index new folders by default to index each repository a terminal moves into.

That page lists each folder as Syncing, Synced with its chunk count, Codebase too large (over 5,000 files) or Failed, with Resync and Delete. Indexes follow your changes; turning Codebase indexing off removes them all.

Indexes are built and kept on this Mac. What .gitignore excludes is left out, and so is what a .kyonindexingignore at the repository's root names, written the same way; the agent can still read those files with its other tools.

Past conversations

Conversations are kept as each turn ends, so you can pick one up later.

Open one from Session › Past agent conversations, or from Left Panel: Agent conversations (⌃2), which lists open and past ones beside your panes. Preferred layout when opening existing agent conversations chooses a new tab or a split pane; Show conversation history in tools panel hides or shows the list. Both are in Settings › Agent › Agent.

Active AI suggestions

Active AI suggests things as you work in the terminal; turn it, or each kind, on or off in Settings › Agent › Suggestions.

  • Next Command offers the next command in the empty input once one finishes, from what usually followed it in your history, or, where that is unclear, from the model, shown your recent commands and output.
  • Prompt Suggestions offers something to ask the agent about a finished command, beside the input. ⌃↩ asks it; ↩ sets it aside.

Omnigent agents

If you run an omnigent server, which runs harnesses such as Claude Code and Codex in sessions, its agents can be a conversation's model.

  • Set Omnigent server in Settings › Agent › Models › Omnigent backend; empty uses KYON_OMNIGENT_URL, else http://localhost:6767. Test connection checks it. Nothing is sent until you test it or ask one of its agents something.
  • Pick Omnigent · Claude, Omnigent · Codex or your own with Change the model for this conversation.
  • Make your own with New agent in Settings › Agent › Profiles › Custom agents: a persona on a harness the server runs, or a folder holding a whole agent package.
  • Start an omnigent agent (Session menu) runs Omnigent command (empty: omnigent) in Omnigent works in, or the current tab's folder.

Limits

MCP servers that need sign-in, and servers using the older SSE transport, are not supported.

Indexing and MCP servers are this Mac's only. Work on a remote host gets neither codebase search nor MCP tools.

Prompt suggestions follow a finished command, not a finished agent reply.

Omnigent on a remote host is tested against a stand-in server, not a real one.

Commit messages and pull requests are not written by a model. The commit dialog starts empty and a pull request is filled from its commits.

Handing a review to a sub-agent runs the coding agent chosen under Ask with, or Claude Code, on the machine the repository is on, not a configured omnigent server.
